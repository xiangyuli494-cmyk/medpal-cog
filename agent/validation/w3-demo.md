## 第一段：跨文档问答

逐一提交 `agent/validation/w3-cases.json` 的四个问题。每题保存：

- 平台原始事件、会话 ID、模型、时间、实际 Skill 事件及 MCP 参数/结果。
- 连续路径的节点、三元组 ID、每一步的真实资产锚点。
- 对应的 trace JSON、溯源完整率、最终三行回答。

前三题是两跳，第四题是三跳。相邻步骤的资产必须不同，完整率至少 0.95。
别名归一、检索调用次数或同文档不同段落均不能充作跨文档跳数。
候选路径应支持问题要求的科室或检查；共享检查项不能推出两疾病具有因果关系。

## 第三段：v0.9 → v1.0 → v1.1

三轮固定问同一个问题，建议选择上述第四题；不在中途换题或换金标准。

| 轮次 | 操作 | 必须保存 |
| --- | --- | --- |
| v0.9 | health → S3 原题 → trace_write | 版本、真实回答、缺口、会话与 trace |
| v1.0 | S1 入库已审核样本 → S2 propose → 展示并确认 diff → commit → S3 原题 | 候选与来源、提交结果、新版本、第一份 diff、回答变化 |
| v1.1 | 重复上述流程，使用第二批已审核样本，再问原题 | 第二份 diff、新版本、回答变化 |

两次分别讲清「新增/修正哪条三元组、来自哪条锚点、因此哪条回答发生变化」。
只改变版本标签、只有图谱条数变化或两次回答无法对应证据变化，均不通过。
回滚有已知未修缺陷时不演示回滚，也不声称已支持可靠回滚。

保存三段屏幕录制及原始流到本地审核目录。没有真实平台事件时不创建 real-*.json，
不把离线回放文件命名成真实会话。当前没有可验收的三轮真实记录或两份进化差分。
