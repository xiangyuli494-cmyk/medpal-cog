## 0 先说规矩（2026-11-02 起生效）

| 规矩 | 具体做法 | 怎么验 |
| --- | --- | --- |
| **不直推 main** | 任何改动（包括只改文档、只改注释）都走分支 + PR | 分支保护 `enforce_admins=true`，owner 直推也会被拒 |
| **必须别人 approve** | T1 的 PR 由 T2（zincumyu）或 T3（Dewqian）批；GitHub 不许自批，这条自动成立 | PR 页面 Reviewers 显示 1 个绿勾；`mergeable_state` 从 `blocked` 变 `clean` |
| **批完再改要重批** | `dismiss_stale_reviews=true`：approve 后又 push，旧批准自动失效 | push 后 PR 顶部出现 "Dismissed stale review" |
| **CI 三绿才算完** | `lint (ruff)` / `test (pytest)` / `pipeline (skeleton + eval)` | PR 底部三个 check 全绿勾 |
| **一次 PR 一件事** | ≤400 行，标题 type(scope): 中文动宾 | 评审人能在 10 分钟内看完 |

T2 怎么批（两种，任选）：

`PR 页 → Files changed → Review changes → Approve → Submit review`

`curl -s -X POST -H "Authorization: token <T2 的 token>" https://api.github.com/repos/xiangyuli494-cmyk/medpal-cog/pulls/<PR号>/reviews -d '{"event":"APPROVE","body":"看完，同意"}'`

> 保护规则实测值（2026-11-02 14:30）：approvals=1、dismiss_stale=true、enforce_admins=true、allow_force_pushes=false、required checks 三个。改规则只能由 T1 跑 `bash tools/gh-protect.sh`，改完在群里说一声。

## 6 T1 的红线

1. **不静默延期**：做不到当场说，写进 backlog，不许拖到截止日。
2. **不编数字**：完整率、对齐率、评测分数必须命令跑出来；编一次整套材料作废。
3. **不替别人改代码**：T2 的本体、T3 的数据，发现问题开 issue，不自己动手（P0 阻塞且对方 24h 无响应除外，事后在 PR 里写明）。
4. **不绕过保护**：不直推、不改保护规则给自己的 PR 放行；规则要改先发 PR 改脚本，由 T2/T3 批。
5. **不把「配置就绪」说成「已实测」**：没在 Nexent 里跑过的就写「配置就绪、未实测」。
