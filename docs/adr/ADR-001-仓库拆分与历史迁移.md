# ADR-001 仓库拆分与历史迁移

- 状态：已采纳（2026-11-01）
- 决策人：T1 xiangyuli494-cmyk
- 影响面：全组六人、CI、CODEOWNERS、评审材料

## 背景

原仓 `medpal` 同时装着两条互不相干的线：

1. **院内智慧陪诊终端**——2026-10-22 冻结（`FROZEN.md` + tag `w1-freeze-20261022`），代码、演示页、小程序设计稿都留在仓里；
2. **赛题3 可进化决策智能体**——六个活人正在写的比赛内容，全在 `agent/` 目录下。

后果很具体，不是审美问题：

- 新人 `git clone` 下来第一屏是陪诊线的 `backend/`、`demo/`、`docs/plan/`，找不到 `agent/` 的入口；
- CI 里四条 workflow 三条跑陪诊线路径，赛题3 的测试反而要「顺带」才跑；
- `CODEOWNERS`、根 `README`、`FROZEN.md` 三处都提到赛题3，读起来像冻结项目的一部分；
- 评审要看的仓库首页，被一条已冻结的产品线的文档盖住。

## 选项

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A 保持单仓 | 在 `agent/` 上继续加，靠 README 区分 | 零成本，但上面的问题一个都不解决；评审第一印象继续被稀释 |
| B 复制目录到新仓 | `cp -r agent/* new/` 后重新提交 | 历史全丢：谁写的、为什么这么改、评审想看演进过程都查不到 |
| C 目录级历史切分 | `git subtree split -P agent` 抽出独立历史，推新仓 | 一次性成本约 1 小时；历史完整、CI 干净、首页就是赛题 |

## 决策

选 **C**。用 `git subtree split` 把 `agent/` 的历史原样搬到新仓 `medpal-cog`，内容提到仓库根（不再有 `agent/` 前缀），旧仓保留原样作为冻结线的归档。

理由：赛题评审会看提交历史（谁做了什么、方案怎么演进），但不会看陪诊线的历史；把历史按目录切开，正好是「该留的留、该断的断」。

## 后果

**变好的**

- 新仓首页就是赛题方案；`git log` 10 个提交全是赛题3的演进，可追溯。
- CI 只跑本仓的东西：lint + pytest + skeleton + eval，三分钟内出结果。
- `CODEOWNERS` 按新路径重写，六个角色各自有地盘。
- 冻结线不受影响：旧仓 `main` 与 tag 原封不动，随时可查。

**要付的**

- 路径前缀被展平，`agent/xxx` 变 `xxx`：17 个文件、158 处引用已批量改完，但**任何外部文档/聊天记录里指向旧路径的链接都会失效**。
- 旧仓不再接收赛题3的提交。有人往旧仓 `agent/` 提 PR，一律关掉并指向新仓（见 `docs/migration.md` 的收尾清单）。
- 两仓之间不再自动同步；确需搬运时用 `git cherry-pick` 或补丁，不做 `subtree merge`（会把两条线重新搅在一起）。

## 回滚

新仓是独立仓库，删掉不影响旧仓；旧仓 `agent/` 与 `main` 一直保留切分时的快照（`9ad29eb` 的父链）。真出问题，从旧仓重新 `subtree split` 一次即可复现，命令见 `docs/migration.md`。

## 不做什么

- 不把旧仓的陪诊线删掉或归档成 `legacy/`：它有自己的 tag 与评审价值，动它没有收益。
- 不做 `git filter-repo` 全局改写：那会重写 132 个提交的哈希，所有人本地库都要重克隆。
