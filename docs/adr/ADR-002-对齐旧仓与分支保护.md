# ADR-002 从旧仓对齐进度，并用分支保护换掉「谁先 push 谁赢」

- 状态：已采纳
- 日期：2026-11-01
- 决策人：T1（队长）
- 相关：[ADR-001](ADR-001-仓库拆分与历史迁移.md)、[冲刺计划 §0/§9](../冲刺计划-1130.md)

## 背景

仓已按 [ADR-001](ADR-001-仓库拆分与历史迁移.md) 从 `medpal` 切出 `medpal-cog`，但切分只取了旧 `main` 的 `agent/` 目录。旧仓还有 4 组在**未合并分支**上的赛题3 成果（本体差分、PDF 解析、决策链可视化页、T3 输入契约）。
同时队里从 6 人缩到 3 人，原来的「T1–T6 各管一块」不存在了；前一轮排期还是「从装环境开始」，与旧仓实际进度（底座 12 项已完成）不匹配。

## 决策

1. **不回旧仓开发，也不重写**：把 4 组未合并成果按文件搬进 `medpal-cog`，改掉 `agent.` 包前缀，补测试，使每个成果在仓内可复现（`ontology/diff.py` 18 测试、`parse/pdf.py` 4 测试、`web/trace.html` 三 fixture、契约文档与两份 fixture）。
2. **排期以「现状矩阵」为准**：先列 R1–R5 的「已有 / 缺口 / 谁补 / 截止」，再按月排任务包；旧仓已完成的 12 项不再出现在任何任务里。
3. **`main` 开分支保护**：必需 PR、≥1 approve、CI 三绿（`lint`/`test`/`pipeline`）、禁强推禁删、要求对话解决。`enforce_admins=false` 保留一个应急阀门。
4. **代号统一为 T1（队长）/ T2 / T3**：旧 T4–T6 并入；旧文档里的 `T1–T6` 作为历史记录保留，不批量改写。

## 备选与为什么不选

| 备选 | 为什么不选 |
| --- | --- |
| 继续在旧仓开发，`agent/` 当子目录 | 旧仓还有陪诊线的 132 次提交与 33 分支、CI 路径、requirements 都绑着陪诊线；每次改动都要证明「没碰坏冻结线」 |
| 只迁 `origin/main`，丢掉未合并分支 | 会丢三份可用代码（差分、PDF、可视化页），重写成本约 4.5 人日 |
| 用 `git subtree` 把旧分支整体合进来 | 旧分支基于旧目录结构，合并会把 `agent/` 前缀和陪诊线历史一起带回来 |
| 只靠「口头约定不直推 main」 | 三个人并行，约定会在最忙的一天失效；保护是机械的 |
| `enforce_admins=true`（队长也不能强合） | 演示前一天如果 CI 因外部原因红了，会集体卡死 |

## 后果

- 好处：旧成果不丢且可复现；排期少了约 4.5 人日；`main` 始终可演示。
- 代价：多两次点击（开 PR、等 approve）；T1 自己的 PR 必须等 T2/T3 有空批——已写进 §9.2 与任务卡。
- 待办：`CODEOWNERS` 里 `@T2_HANDLE` / `@T3_HANDLE` 仍是占位符，两人加进 Collaborator 后替换并开启 `require_code_owner_reviews`。
