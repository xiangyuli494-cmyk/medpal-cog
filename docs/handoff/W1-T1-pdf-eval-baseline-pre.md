## 3. 已知风险与 Backlog

### 3.1 PDF标题正则误匹配
- **现象**：`PDF_SECTION_RE` 正则中的 `\d+(?:\.\d+)*` 规则会把普通数字开头文本误判为标题
- **复现场景**：`pdf_03_number_title.pdf` 中 "3.5万样本说明" 被识别为 heading
- **预期行为**：应以字数、上下文判断，而非纯数字格式
- **影响范围**：仅 PDF 解析标题识别，不影响正文提取
- **后续计划**：单独开 PR 优化正则，增加白名单/上下文校验

### 3.2 PDF标题不识别字体大小
- **现象**：纯靠正则匹配标题格式，不看字号大小
- **复现场景**：`pdf_05_font_size.pdf` 中 20号字大标题 "消化性溃疡诊疗规范" 未被识别为 heading
- **预期行为**：大字号文本应优先判定为标题
- **影响范围**：仅标题识别准确率
- **后续计划**：结合 PyMuPDF 的 span size 信息辅助判断

### 3.3 表格异常静默吞错
- **现象**：`page.find_tables()` 出错时 `except: tables = None`，不上报错误
- **复现场景**：暂未触发（本次表格样本解析正常）
- **后续计划**：增加 table_errors 计数写入 metadata

### 3.4 ✅ 已实现：异常容错降级（本次新增）
PdfParser 已增加统一异常捕获，所有错误不直接抛异常，统一写入 `metadata`：

| error_type | 触发场景 | 返回信息 |
|-----------|----------|---------|
| ENCRYPTED_PDF | 加密PDF | "PDF文件已加密，需要密码才能读取" |
| NO_EXTRACTABLE_TEXT | 扫描件/空白PDF | "当前PDF仅包含图片，无原生可提取文本（扫描件）" |
| CORRUPTED_FILE | 文件损坏 | "PDF文件损坏或不是合法PDF格式" |
| UNKNOWN_ERROR | 其他异常 | "解析异常: {错误信息截断100字}" |

> 设计原则：上层 MCP 调用不用单独 try-catch，统一返回 ParsedDoc 结构，通过 metadata.error_type 判断异常。
