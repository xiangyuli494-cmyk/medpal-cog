## 2. S3 试跑（工具层直调）

### 2.1 试跑目的

S3 的机制核心是「检索不是一次性投喂，推理会反过来提出新的检索需求」。定稿前需要确认三件事能真跑通：

1. 口语主诉能被 `std_align` 归一成实体；
2. `kg_query` 两跳能召回带 `anchor_id` 的证据；
3. `trace_write` 能落链并算出溯源完整率。

### 2.2 试跑输入

主诉：「上腹隐痛三月伴烧心，该看哪个科、做什么检查」

### 2.3 第 1 步：实体归一（`std_align`）

| 输入（口语） | ok | code | match |
|---|---|---|---|
| 上腹隐痛 | true | SYM-EPI | exact |
| 烧心 | true | SYM-HEART | exact |
| 肚子痛 | **false** | — | unmapped |
| 上腹痛 | **false** | — | unmapped |
| 止疼药 | **false** | — | unmapped |
| 呼气试验 | **false** | — | unmapped |

命中 2/6，四个口语说法全部 `unmapped`。

### 2.4 第 2 步：两跳检索（`kg_query`）

- 种子：`["上腹隐痛", "烧心"]`，`max_hops=2`，`limit=20`
- 返回：`ok=true`，`resolved=["SYM-EPI","SYM-HEART"]`，`unresolved=[]`，**paths 20 条**
- 抽两条有代表性的路径：

```
胃食管反流病 -[has_symptom]-> 烧心            T-231b3ff2  anchor: AST-2026-000137#s1.h
上腹隐痛 -[diagnosed_by]-> 消化性溃疡          T-83aeffed  anchor: AST-2026-000137#s2.p1.c3
```

命中的锚点共 6 个（去重后）：

```
AST-2026-000137#s1.h   AST-2026-000137#s2.p1.c2   AST-2026-000137#s2.p1.c3
AST-2026-000137#s3.p1.c1   AST-2026-000137#s3.p1.c2   AST-2026-000137#s4.p1.c2
```

### 2.5 第 3 步：落链（`trace_write`）

```
trace_id            TR-20261111-3E72
version             v0.9
evidence_count      6
trace_completeness  1.0
unresolved          []
report_path         mcp-server/reports/TR-20261111-3E72.md
```

结论：**三步闭环成立**——口语→归一→两跳证据→落链，每条证据可回溯到原文锚点，溯源完整率 1.0。

### 2.6 复现方式

```bash
python tmp/s3_trial.py        # 脚本会先把交付库复制到 tmp/s3-run/ 再跑，不写交付库
```

脚本本身在 `tmp/`（gitignore，不入库）。若要长期复现，建议后续挪到 `tools/s3_trial.py` 并加 `--db` 参数。

## 3. 试跑暴露的两个问题（本次只记录，未改）

### 3.1 `std_align` 的 alias 表落后于 `parsers.SYNONYMS`（真实缺陷）

`mcp-server/seed.py:74` 的 `ALIASES` 只有 12 个 surface：上腹部痛、上腹隐痛、消化性溃疡、胃溃疡、胃炎、胃食管反流、烧心、反酸、幽门螺杆菌、胃镜、布洛芬、消化内科。

而 `mcp-server/parsers.py` 的 `SYNONYMS` 里还有 `肚子痛 / 上腹痛 / 上腹不适 / 止痛药 / NSAIDs / 呼气试验 / 胃食管反流 / 反酸` 等映射。两套词表不一致，结果是：**解析器抽出来的口语实体，`std_align` 归不回去**，S3 第一步就会在「肚子痛」这类最常见的说法上失败，并直接导致 `kg_query` 报 `no_seed`（首次试跑就是这个现象）。

建议：让 `std_align` 复用 `parsers.SYNONYMS`，或把 `ALIASES` 补齐到与 `SYNONYMS` 同集合，并加一条 pytest 断言「两表 surface 集合包含关系成立」。这属于 `mcp-server/` 范围，归 T2。

### 3.2 `kg_query` 只返回 `paths`，没有顶层 `triples`（易用性）

返回值结构是 `paths[]`，每条 path 里嵌 `steps[]`（带 `triple_id / anchor_id / confidence`）。SKILL.md 写「取 2 跳路径」是对的，但调用方如果按 `triples` 取会拿到空列表——第一次试跑就踩了这个空。

建议二选一：在 docs 里明确「kg_query 只回 paths，三元组在 path.steps 里」，或在返回里补一个 `triples` 平铺字段。属文档/契约口径，建议与 T2 一起定。
