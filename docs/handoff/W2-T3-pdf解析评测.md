## 2 改了什么契约

| 契约 | 变化 | 谁要跟着改 |
| --- | --- | --- |
| 无 | — | — |

**没有 MCP 契约变更、没有新增错误码。** 异常 PDF 沿用 `main` 现有的处理链：
`PdfParser` 把损坏/加密/无原生文本写进 `metadata["error"]` → `server.py:78-79` 统一返回
`{"ok": false, "reason": "parser_unavailable", "hint": <具体原因>}`，契约 §3 原封不动。

一处**待确认的文档口径**（本 PR 未改，交给 T2）：

- `docs/mcp-contract.md` §1.2 写的是 pdf_text 锚点 `p{页}.s1`（整页）；
- `main` 的解析器实际产出 `p{页}.h{节}` / `p{页}.s{节}.p{段}` / `p{页}.t{表}.r{行}`；
- 评测只断言锚点唯一、挂在 asset_id 上、可按页分组，不写死编号规则，所以两种口径都能过；
- 建议 T2 在契约里补一句实际格式，避免下游按 `p{页}.s1` 解析时对不上。

## 4 已知问题与坑

| 现象 | 原因 | 绕法 / 待办 |
| --- | --- | --- |
| 编号列表整页被判成标题，长文档 0 段落 | `PDF_SECTION_RE` 只看「数字开头」，正文每行 `1.1 / 1.2` 开头也命中 | 已修：加句子标点闸门（含 `。` 或以 `。；;：:，,` 结尾的按正文） |

| 扫描件（无文字层）返回失败而非 ok | `main` 有意判为 `NO_EXTRACTABLE_TEXT`，避免生成 0 块的空卡 | 用例期望已订正为 `fail`，并新增「不建幽灵卡」断言；OCR 兜底不在本周范围 |

| 样本不入库，换机器要重跑生成器 | `tmp/pdf-fixtures/` 在 gitignore 内，保可复现优先于入库 | 验之前先跑 `tools/gen_pdf_fixtures.py` |
