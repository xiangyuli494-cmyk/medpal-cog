## 1 这次做了什么

- 新增生成器 `tools/gen_ledger.py`：读 `data/asset-cards/*.json` 渲染成单文件 `web/ledger.html`；`--check` 只校验不写盘；产物不带时间戳，同输入重复跑逐字节一致。
- 新增台账页 `web/ledger.html`：把当前 **62 张卡**逐行列出（资产号 / 标题 / 模态 / 来源 / 锚点 / 实体 / 知识库状态），单文件 36 KB、**0 外链**（无 http、无 `src=`、无 `@import`），双击即开，不依赖任何进程。
- 页面提供搜索、模态筛选（含 W1 新增的 `pdf_text`）、「只看告警」开关；告警区按 S1 口径分列：缺模态 / 锚点数为 0 / 实体为空 / `source.path` 是本机绝对路径。
- 把 `web/ledger.html` 加进 `tools/acceptance.py` 的 A-13 必备入口清单，A-13 由 24 项变 25 项，从「交付物」升级成「闸门会红」的条目。
- 新增 `tests/test_ledger.py` 三条：页面是否为最新、是否覆盖每张卡、是否泄漏盘符路径。

## 4 已知问题与坑

| 现象 | 原因 | 绕法 / 待办 |
| --- | --- | --- |
| 页面是 62 张，不是任务卡写的 61 张 | W1 的 T3-1 又入了 1 张 `pdf_text` 卡（`AST-2026-7e430e`）；A-05 口径是「只增不减」 | 页面按真实卡数出，不写死 61；生成器只用 `MIN_CARDS=61` 做下限 |
| 61 / 62 张卡的 `source.path` 是本机绝对路径（`E:\deepseek-data\medpal-cog\data\...`） | 写卡那侧记的是运行时绝对路径 | 页面显示时归一成 `data/samples/...`，并在告警区点名；数据面修复点在 `mcp-server/server.py`，归 T2（与 PR #27 评审第 1 条同款） |
| 21 张卡实体为空（`image_report` 20 + `table` 1） | 图文/表格样本没抽实体 | 按 S1 口径列进告警、不当作成功入库；补实体归 T2 |
| 图上/首轮归一踩的坑：`repo_relative` 一开始把 `deepseek-data` 里的 `data` 当成仓库根 | `find("data/")` 会命中目录名的一部分 | 只认 `data/` 开头或 `/data/` 整段；已改成这个写法并重新生成 |
| PR 行数 612 > 「≤400 行」 | 其中 193 行是生成产物 `web/ledger.html`（CSS/JS 骨架 + 62 行数据） | 评审只看 `tools/gen_ledger.py`；页面内容由 `--check` 保证与卡一致 |
