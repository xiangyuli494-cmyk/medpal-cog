## 3.1 与 `acceptance --stage w2` 的兼容（11-13 的修复）

评审指出的必改：CI 绿、但合并后跑一次 `python tools/acceptance.py --stage w2` 必红。复核后根因比「卡数 62→69」更深一层：

- 闸门会先跑 `seed --reset` + `ingest_all`，把 `data/samples` 里尚未登记进仓库的样本写成卡：**62 → 69 张**；
- 它还会**重写卡 id**——实测基线卡 `AST-2026-c87d1e` 在 ingest 后就不存在了，所以工作区的卡集合既不是基线的超集，也逐张对不上；
- 已提交的页面是按 62 张基线卡生成的，于是 `test_ledger_is_up_to_date` 的严格相等断言在任何一次闸门运行里都会失败（首跑 `1 failed, 78 passed`，二跑 `1 failed, 79 passed`）。

改法（保留页面入库，不牺牲 T3-3「双击可开」的可评审性）：页面自己带一份基线清单 `<meta name="ledger-baseline">`，判据分两种状态——

| 状态 | 判据 |
| --- | --- |
| 卡目录与基线一致（正常开发态、干净 clone） | 页面必须与 `build_page(load_cards())` **逐字节相等**；改了卡不重生成就红 |
| 卡目录漂移（跑过 `ingest_all`） | 只做结构校验：基线清单在、每张基线卡都渲染进页面、行数=基线数、无盘符路径 |

两种状态都不放宽的三条硬线：`MIN_CARDS=61`、无盘符路径、逐卡覆盖。

证据（临时 worktree 里 detached 到修复提交，连跑两次闸门）：

```text
PASS 14 / FAIL 2 / MANUAL 3      # 修复前：A-01 pytest 1 failed（台账用例）
PASS 14 / FAIL 2 / MANUAL 3      # 修复后第 1 次：A-01 退出码 0，A-04 69 卡
PASS 14 / FAIL 2 / MANUAL 3      # 修复后第 2 次：A-01 退出码 0，A-04 69 卡
未通过：A-07(活跃三元组 ≥50)、A-09(本体快照 ≥2 个)   # 这两条归 T2/#27，与本 PR 无关
```

反向验证（会不会把「改卡忘重生成」也放过去）：在干净副本里把一张卡的标题改掉再跑测试，仍然是红——

```text
E   AssertionError: web/ledger.html 与当前资产卡不一致，重跑 python tools/gen_ledger.py
FAILED tests/test_ledger.py::test_ledger_matches_cards_or_covers_baseline
```

顺带查清的一个数据面事实（不属本 PR 修复范围，记在这里免得下次重复排查）：仓库里 62 张卡 ≠ 流水线产出的 69 张，差额 7 张是 `ingest_all` 每次从 `data/samples` 现场造出来的、从未入版本管理的卡；且 ingest 会重写已入库卡的 id。这条归 T2/T1 决定「要不要入那 7 张、id 该不该稳定」。

页面自检（生成器内部断言，不通过就直接 exit 1，不写盘）：

```text
FAIL 资产卡只有 61 张，少于下限 61 张（A-05）        # 卡数下限
FAIL 生成页里出现 N 处盘符路径，绝对路径泄漏        # 盘符路径正则 [A-Za-z]:[\\/]
FAIL <asset_id> 没有出现在台账页里                 # 逐卡覆盖
FAIL 台账页行数与资产卡数量不一致                   # 行数=卡数
```

## 4 已知问题与坑

| 现象 | 原因 | 绕法 / 待办 |
| --- | --- | --- |
| 页面是 62 张，不是任务卡写的 61 张 | W1 的 T3-1 又入了 1 张 `pdf_text` 卡（`AST-2026-7e430e`）；A-05 口径是「只增不减」 | 页面按真实卡数出，不写死 61；生成器只用 `MIN_CARDS=61` 做下限 |
| 61 / 62 张卡的 `source.path` 是本机绝对路径（`E:\deepseek-data\medpal-cog\data\...`） | 写卡那侧记的是运行时绝对路径 | 页面显示时归一成 `data/samples/...`，并在告警区点名；数据面修复点在 `mcp-server/server.py`，归 T2（与 PR #27 评审第 1 条同款） |
| 21 张卡实体为空（`image_report` 20 + `table` 1） | 图文/表格样本没抽实体 | 按 S1 口径列进告警、不当作成功入库；补实体归 T2 |
| 图上/首轮归一踩的坑：`repo_relative` 一开始把 `deepseek-data` 里的 `data` 当成仓库根 | `find("data/")` 会命中目录名的一部分 | 只认 `data/` 开头或 `/data/` 整段；已改成这个写法并重新生成 |
| PR 行数 612 > 「≤400 行」 | 其中 193 行是生成产物 `web/ledger.html`（CSS/JS 骨架 + 62 行数据） | 评审只看 `tools/gen_ledger.py`；页面内容由页面内基线清单 + `--check` 保证与卡一致 |
