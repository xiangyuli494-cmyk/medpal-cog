## 4 返工与教训

1. **误提交玩具文件（本 T3 自己踩的）**：为了绕开本地 git 网络问题，把两个临时评测文件（`eval/asset/s1_asset_eval.jsonl`、`eval/asset/eval_s1.py`）从 GitHub 网页直接建进了 PR #28，后来必须再开一个提交撤掉（`1c277f0`）。
   **教训：网页建文件之前先问「这是交付物还是临时脚本」，临时脚本一律不进仓库。**
2. **台账页生成器的两个真 bug**：① PDF 卡被当成未知模态、筛选按钮缺一类；② `repo_relative` 用 `find("data/")` 把 `E:\deepseek-data\...` 里的 `data` 误当成仓库根，路径显示成 `data/medpal-cog/data/...`。改成只认 `data/` 开头或 `/data/` 整段才对。
   **教训：路径归一不能靠子串查找，要按分隔符认段边界。**
3. **评测口径坑**：`run_eval.py` 的临时库是 `seed.py` 的 17 条基座三元组建的，**不是** 61 条 `ontology_v1.0.jsonl`。所以「六项 1.0」只说明确定性链路没问题，**不能读成 v1.0 本体的能力分**；写材料时一律加一句限定。
4. **闸门必须在临时副本里跑**：`acceptance.py --stage w2` 会连带跑 ingest，往 `data/asset-cards` 里写新卡 —— 实测一次跑完卡数 62 → 69、70 个文件变动。直接在主工作区跑会把一堆未跟踪卡留在树里。**做法：`git worktree add --detach` 到临时目录跑，跑完 remove。**
