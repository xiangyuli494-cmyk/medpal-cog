## 4 本轮修掉的两个真缺陷

### 4.1 科室回显（第一版就有，判据写错了）

**现象**：问「甲状腺结节，需要看消化内科吗」，输出「消化内科」——把用户的疑问对象当结论。

**第一版修法**：`if set(seed_types) <= {"Department"}:` 清空结论。
**问题**：只挡「整句除科室外再没有可归一实体」的问法。评审复核实测：

| 问句 | 第一版输出 | 修后 |
| --- | --- | --- |
| 体检发现甲状腺结节，需要看消化内科吗 | 消化内科（错） | 拒答 |
| 需要看消化内科吗 | 消化内科（错） | 拒答 |
| 最近胃疼，要挂消化内科吗 | 消化内科（错） | 拒答 |
| 长期吃止痛药，需要看消化内科吗 | 消化内科（错） | 拒答 |
| 我做过胃镜了，还要看消化内科吗 | 消化内科（错） | 拒答 |

后两句的实体集合是 `{Drug, Department}` 与 `{Exam, Department}`，`<= {"Department"}` 不成立，
清空逻辑根本没走到。

**这一版的判据换成问句意图**：问句里出现科室名 + 出现「挂哪个科 / 需要看 / 还要看 / 该看…」
这类征求科室选择的措辞 + 句中没有疾病或症状（只有药或检查项这类非定科信号）→ 不给科室结论。
`上腹隐痛、反酸烧心，挂哪个科` 有症状，照常答消化内科，不受影响。

**还没解决的边界**：判据仍是「有没有症状/疾病」，不是真正的意图分类。
将来出现「既点了科室、又顺带提到症状」的问法仍会走到正常路径——这属于把判据做成分类器才能根治的活，记在 backlog。

### 4.2 证据召回的空满分母（评审 P1，这是本轮最重要的修复）

**现象**：`evidence_recall` 一直显示 1.000，看起来满分。

**根因**：`eval/run_eval.py` 主循环写的是 `score_one(row["gold"], got)`，
而 `gold_evidence` 写在 dataset 每行的**顶层**，不在 `row["gold"]` 里；
`score_one` 内部 `set(gold.get("gold_evidence", []))` 拿到的恒为空集 → 直接返回 `1.0`。
把 Q025 的 `got.evidence` 置成 `[]` 仍得 1.0——这一项当时**没有在测任何东西**。

**修法**：
- `score_one(gold, got, gold_evidence)`，调用方显式传 `row.get("gold_evidence")`；
- 声明了锚点就必须真比对，输出证据为空时得 **0**，不是 1.0；
- 负例与无锚点题返回 `None`，**不进分母**（`evidence_n` 与实际参与条数一起写进报告）；
- 加 `tests/test_eval_evidence.py` 四道锁：空证据得 0、半命中 0.5、负例不进分母、
  `v1` 全量重算不得退回 0.9 以上（退回就是又变回空满分母）。

### 4.3 三跳从来没被测过（评审 P2，本轮补上）

**现象**：`answer(conn, question)` 固定 `max_hops=2`，dataset 每行的 `hops` 字段（0/2/3）
根本没被读；也没有路径长度、跨文档断言。所以「W3 三跳已验收」这句话在当时是空的。

**修法**：
- 主循环按 `row.get("hops")` 传 `max_hops`，`score_one` 显式收 `gold_hops`（理由同 4.2：别再读错地方）；
- 新增两项指标写进报告：**跳数达成**（声明 n 跳的题是否真走出 n 跳）、**三跳跨文档**
  （最长路径的 provenance 跨了几份文档）。分母条数一起报（`path_n` / `cross_doc_n`），空分母不算满分；
- 退回默认 2 跳时，声明 3 跳的题跳数达成得 0——旧行为会被 `tests/test_eval_multihop.py` 抓出来。

**实测（v1 30 条）**：
- 跳数达成 **1.000**（25 条声明 ≥2 跳；11 条声明 3 跳的题最长路径确实到了 3 跳）；
- 三跳跨文档 **0.000**（11 条声明 3 跳，最长路径的 provenance **全部落在 `AST-2026-000137` 一份文档**）。
  也就是说：三段关系链有了，但它在同一份文档里，不构成跨文档推理。
  **这条如实记成未达标，不拿「路径有三跳」冒充「跨文档三跳已验收」。**
  要真跨文档得靠本体把不同资产的三元组串起来（本体侧，和 A-07 同一个口子）。

#### 三种方案的情景估算（逐题假设写在这里，给 T1 决策用）

**这三种都是按逐题假设计算的情景值，不是实测**（分母恒为 21，负例与无锚点题不计入）。

| 方案 | 逐题假设 | 得分 | 与 B-05(≥0.90) 的关系 |
| --- | --- | --- | --- |
| ① 只补边（不动题库、不补卡） | 4 条半分题补边后转满分（+2）；Q025/Q026 的 4 个「卡有未入图」锚点补边后转满分（+2）；7 条真缺锚点题仍 0 | `(8+4+2)/21 = 14/21 = **0.667**` | **不过** |
| ② 只改题库（9 条 0 分题换成已入图的锚点，其余不动） | 9 条 0 分题全转满分（+9）；4 条半分题保持 0.5（+2） | `(8+9+2)/21 = 19/21 = **0.905**` | **压线过**（仅高 0.005） |
| ③ 补边 + 另建 id 映射（把 3 个缺失锚点映射到卡内真锚点）+ 题库不动 | 全部 21 条转满分 | `21/21 = **1.000**` | **过**（理论上限） |

四条说明，把结论说清楚：

- **① 是关键结论**：只靠本体补边最多 0.667，**#31 修完也不会让 B-05 变绿**，A-07 转 PASS 带不动 B-05。
- **② 单独也能过线（0.905）**，所以「必须两条一起」不成立——这是我在上一版写错的地方（上一版 0.810
  对应的是「9 条里只有 7 条换了锚点」这种没写明的假设，已删）。但 ② 的性质是**事后挑锚点**：
  分母 21 不变、把不存在的锚点换成好锚点分数就上去，不建议拿它对外报分。
- **③ 其实不干净，补解析补不出来**（11-19 修正，原写「解析漏段，属入库侧」是错的归因）：
  `#p2.s3` / `#p3.s5` / `#p4.s7` 是「页.节」两段式 id，而 `AST-2026-000137` 是 `.md` 资产，
  卡里 15 个锚点全是 `sN.h` / `sN.pN.cN`（5 个小节标题 + 10 句，一句没漏）——
  文本解析路径没有「页号」这一维，怎么补都补不出 `pN.sN` 来。
  两段式 `p%d.s%d` 只在 PDF 解析路径、且只在**未合并**的 `feat/t3-pdf-parser` 分支（`b1f74d9` 等）
  出现过；main 现行 PDF 锚点是 `p%d.h%d`（标题）和 `p%d.s%d.p%d`（段）。
  所以 ③ 真正能落地的只有两条：把题库锚点改到卡内真实锚点（性质就退回 ②），
  或**另建一张 dataset 声明 id → 卡内锚点 的映射表**（人工逐条指定，谁拍谁定）。
  这条也和「4 个锚点定位错」是同一类问题：别把人送到做不到的路上。
- ①+②+③ 都不需要动阈值。若 T1 决定 W3 只按「五项达标」验收，就把 B-05/B-08 记成
  「已知缺口 + 真值 0.476」，也不改阈值。
