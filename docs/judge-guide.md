# 评审动线：从进门到信服，八分钟

评委不会读完 747 行方案。这份动线保证**八分钟内**看到赛题要的四件事都在动。

## 0 先给一句话（20 秒）

> 我们只切一条链路：门诊主诉 → 跨文档取证 → 科室与检查建议。自研 1 个 MCP Server（10 个工具）、3 个 Skill、1 个主智能体跑在 Nexent 上。**所有结论都带证据锚点，找不到证据就说不确定**——这是医疗场景能不能用的分水岭。

## 1 仓库首页（60 秒）

打开本仓，指三块：

- `README.md` `1` 状态表：哪些能跑、怎么验（不用听我们讲，命令就在旁边）；
- ``2` 要求对照表：R1–R5 每条对应哪个交付物；
- `data/asset-cards/`：61 张卡片，随便点开一张，看模态、来源、版本、可引用锚点。

## 2 现场跑（2 分钟）

```bash
python mcp-server/seed.py --reset
python skeleton.py
python -m pytest tests -q
python eval/run_eval.py
```

讲法：**骨架先通，指标才有意义**。`skeleton.py` 是一条最小主线——一条主诉进来、走完 5 步、出科室与检查建议、带上溯源完整率。它绿，说明链路通；它红，别谈分数。

## 3 「可进化」三连（3 分钟，这是赛题的核心分）

| 演示 | 操作 | 要看到的 |
| --- | --- | --- |
| **本体会长** | 喂一份新文档 → `onto_propose` → 人工确认 → `onto_commit` | 版本 v0.9 → v1.0，候选里有新增/修正/废弃三类，旧快照还在 |
| **决策会变** | 用同一批题再跑一次 | 至少一条结论变化，且能说清「因为新增了哪条证据」 |
| **能力会沉** | 对一次成功执行调 `skill_export` | 出一份 SKILL.md 草稿：步骤序列、每步用的工具与锚点 |

关键一句：**不是模型变强了，是它记住的东西变多了**——本体是记忆，模板是经验，版本号是证据。

## 4 溯源（1 分钟）

打开一份 `trace_write` 出的报告，逐行指 `asset_id` / `anchor_id` / `triple_id`。反问评委一句：**如果这条建议错了，我们能不能查到它是从哪份文件的哪一段推出来的？** 能，就是我们要的答案。

## 5 边界（30 秒，主动说，别等问）

不做：诊断结论、处方剂量、影像 AI 判读、多轮随访、HIS/EMR 对接。数据只用公开标准 + 合成样本，仓库里没有任何真实患者信息。

为什么主动说：**医疗 AI 的可信度来自知道自己不该做什么**。把边界说清楚，比多做一个功能更能过评审。

## 常见提问与答法

**Q：这不就是检索增强生成？**
A：RAG 只做召回；我们多了三层：本体多跳（跨文档的实体关系）、冲突检测（两份文档说法不一致时标出来）、决策链落盘（每一步的证据与版本都可复核）。`kg_query` 返回的每条路径都带 `triple_id` 与 provenance。

**Q：为什么自研 MCP Server，不用现成的？**
A：赛题要「深度集成」。现成工具集会让我们在「医疗实体归一 / 本体版本管理 / 决策链」这三件事上做不了，而这三件正好是评分点。自研的代价是 10 个工具的维护成本，收益是每一步都能挂证据。

**Q：离线评测 100% 是不是自己出题自己考？**
A：是，所以我们不把它当答辩分。它的作用只有两个：回归（改代码别改坏）、上限参照。真实分数在 Nexent 里用同一份 `eval/dataset/v0.jsonl` 跑平台评测，两套分数对不上就说明智能体层有额外损耗——这本身是个可讲的发现。

**Q：六个怎么分工的？**
A：T1 架构与契约、T2 知识工程与推理、T3 前端与可视化、T4 本体与标准对齐、T5 数据检索与评测、T6 环境与 CI。契约先行（`docs/mcp-contract.md`），所以六个人能并行。

**Q：现在到什么程度？**
A：MCP 十工具、三 Skill、61 张资产卡、本体 v0.9、离线评测链路全部可跑；Nexent 平台侧接入是 W2 的任务，三条路径已经写好（远程 MCP / API 转 MCP / 容器同网）。不夸大：**平台集成是我们现在的短板，也是接下来两周的全部重点。**
