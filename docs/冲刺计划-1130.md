## 6 裁剪清单（做 / 不做 / 降级）

**保留做厚**

1. 10 个 MCP 工具 + 3 个 Skill 包（评委直接看得见的能力面）
2. 可进化三行为：本体会长、决策会变、能力会沉——**现场演，不靠 PPT 讲**
3. 决策链溯源：每一步都要有 `anchor_id`，断链要显式标红
4. 一条命令起重（`tools/selfcheck.py`）+ 离线评测报告 + 静态页演示（`web/trace.html`）

**降级**

| 原计划 | 降级为 | 理由 |
| --- | --- | --- |

| 图像视觉模型 / OCR | 已标注 `image_report` 卡（20 张） | 训练不产出可演示增量；PDF 走文本层解析 |
| 自建向量库 / Neo4j | Nexent 知识库 + SQLite | 存储不是评分点 |

**不做（写进边界声明，答辩主动讲）**

- 不覆盖全科室、不做处方与用药建议（只到「科室 + 检查」）
- 不做多租户 / 权限体系 / 移动端 / 小程序
- 不接真实医院数据，全部公开可开源数据 + 合成数据

### 9.2 `main` 的保护规则（已开，改不了就找 T1）

| 规则 | 值 | 为什么 |
| --- | --- | --- |
| 必须走 PR | 是（对非管理员硬拦） | 分支保护会拒掉非管理员的直推；**T1 是 admin，`enforce_admins=false` 期间仍能绕过**（见下一行），属已知例外，纪律上不许绕 |
| 批准数 | **≥1** | 「点 approve 才能合并」 |
| 新提交后旧批准失效（dismiss stale） | 是 | 批完又改代码不算批过 |
| 必须 CI 绿 | `lint (ruff)` / `test (pytest)` / `pipeline (skeleton + eval)` 三个 check（是 job 的 `name:`，不是 job id） | 名字改了要重跑 `bash tools/gh-protect.sh`，否则 PR 会一直等不到状态 |
| 对话必须解决 | 是 | 评论未 resolve 不许合 |
| 允许 force push / 删分支 | 否 | 历史只增不改 |
| 管理员也受限 | **暂否**（`enforce_admins=false`）；T2/T3 进 collaborator 当天改 **是** | 实测（11-01）：阀门是开着的——owner 直推 `main` 会成功，远端只打印 `Changes must be made through a pull request` 警告。所以「不直推」在开 `enforce_admins` 前靠自觉；命令：`ENFORCE_ADMINS=1 bash tools/gh-protect.sh` |

> **谁批谁**：T2/T3 的 PR 由 T1（或另一名队员）批；**T1 自己的 PR 必须由 T2 或 T3 批**——GitHub 不允许自己批自己的 PR，这条自动成立。

### 9.3 一次 PR 的完整动线

```bash
# 1) 从最新 main 开分支
git switch main && git pull --ff-only && git switch -c feat/kg-2hop

# 2) 小步提交，信息一行说清
git add -A && git commit -m "feat(kg): kg_query 支持两跳并返回路径锚点"

# 3) 自检（CI 跑的就是这三条 + skeleton）
python tools/acceptance.py --with-eval && python tools/selfcheck.py && python -m ruff check .

# 4) 推分支、开 PR（网页点也行）
git push -u origin feat/kg-2hop

# 5) 拿 1 个 approve 后由 T1 合并；合并用 squash，历史干净
```

**PR 要求**：≤400 行；贴证据（命令输出 / 截图 / 报告路径）；标题同提交信息格式；模板已带自查清单。

### 9.4 交接单（不进合并门槛，周闸门要核对）

合并门槛只有 CONTRIBUTING §3 那五条（CI 三绿 + acceptance + 一张 approve）；交接单不卡合并，但周日闸门核对证据位时会找它。

`docs/handoff/W{周}-{代号}-{模块}.md`，四节：干了什么 / 数据流 / 改了什么 / 怎么验证。模板见 `docs/handoff/TEMPLATE.md`。

### 9.5 合并后

合并即删分支（GitHub 默认勾选）；每周日闸门后由 T1 打一个 `w{N}` 轻量 tag 便于回溯；发版打 `v1.0`。
