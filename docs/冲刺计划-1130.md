## 5 裁剪清单（做 / 不做 / 降级）

**保留做厚**

1. 10 个 MCP 工具 + 3 个 Skill 包（评委直接看得见的能力面）
2. 可进化三行为：本体会长、决策会变、能力会沉——**现场演，不靠 PPT 讲**
3. 决策链溯源：每一步都必须有 `anchor_id`
4. 一条命令起重（`tools/selfcheck.py`）+ 离线评测报告

**降级**

| 原计划 | 降级为 | 理由 |
| --- | --- | --- |
| Streamlit 台账页 | 生成静态 HTML（脚本 `tools/build_pages.py`） | 少一个进程、少一类现场故障 |
| 评测 50 条 | 30 条（20 必做 + 10 加分） | 20 条足够出六项指标，50 条会把 W3 吃光 |
| 图像视觉模型 | 已标注 `image_report` 卡（20 张） | 训练不产出可演示增量 |
| 自建向量库/Neo4j | Nexent 知识库 + SQLite | 存储不是这题的评分点 |

**不做（写进边界声明，答辩主动讲）**

- 不覆盖全科室、不做处方与用药建议（只到「科室 + 检查」）
- 不做多租户 / 权限体系 / 移动端
- 不做独立前端工程与构建链
- 不接真实医院数据，全部公开可开源数据

## 10 验收标准（可执行）

> §9 说「交什么」，本节说「怎么算交到了」。每条都带命令与期望值；跑不出来就不算完成。

### 10.0 六条判定规则

1. **四件齐**：编号 / 命令 / 期望 / 证据。没有命令的条目直接删掉，不留在表里。
2. **PASS 才算完成**：FAIL 或「还没跑」一律记未完成，当轮不进 `main`；连续两轮 FAIL 升级到 §7 风险登记。
3. **默认自动判定**：`python tools/acceptance.py --stage <周>`，加 `--with-eval` 连评测指标一起判。它就是本节 10.1–10.2 的执行体，改标准就改它，别只改文档。
4. **三项人工（MANUAL）**：容器数、MCP 远程可达、控制台工具可见——需要 Docker daemon，命令照抄，结果贴 `docs/handoff/` 交接单。
5. **指标不许靠删题达标**：`eval/dataset/*.jsonl` 只增不删；删题、改金标准必须在 PR 描述写理由并由 T0 批准，否则该次评测作废。
6. **三档阈值**：baseline（现在就得绿）/ 周闸门 / 11-30 交付；同一口径上的旧指标任何时候不许退。
